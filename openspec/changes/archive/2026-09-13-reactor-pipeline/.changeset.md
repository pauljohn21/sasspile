# Reactor Pipeline Change

## Why

当前 sasspile 在管线表层有链式 API, 但 evaluate() 内核是 God-object + &mut Env + 隐式 IO。这导致:
- 隐式共享状态使 bug 难以复现
- 无法 mock IO, 测试依赖文件系统
- 错误定位依赖全量 trace, 无法精确到阶段边界
- 不符合 AGENTS.md 函数式哲学

## What Changes

- **ADD**: `Reactor` 核心类型, 消费-返回 API, 类型状态机管线
- **ADD**: `ReactorIO` trait 抽象文件 IO, mock 测试能力
- **ADD**: OTel 链式追踪 — 每次阶段推进 = 一个 span, 父子关系自动建立
- **ADD**: `imbl::HashMap` 持久化 Env/Scope (imbl 是 im 的维护活跃 fork)
- **ADD**: Color `scale/adjust/change/to_space/to_gamut` 链式 trait method
- **DELETE**: 旧 `Evaluator` God-object (2000 行 &)mut self 方法群)
- **DELETE**: `Env` interior mutability (Rc::RefCell pattern)
- **MODIFY**: `eval_*` 函数签名统一为纯函数形式 `(Reactor, input) -> (Reactor, output)`

## Impact

- **Affected specs**: 新增 reactor-core / reactor-env / color-ops 三类 spec
- **Affected code**:
  - `src/eval/mod.rs` — Evaluator 删除, Reactor 引入
  - `src/eval/env.rs` + `env_impl.rs` + `scope.rs` — 持久化化改造
  - `src/eval/builtin/color_*.rs` — Color chain API 适配
  - `Cargo.toml` — 新增 `imbl` 依赖
- **Affected tests**: 所有 OTel 测试需验证链式 span 层级
- **Breaking**: 公开 API `Source::lex().parse()...` 保持不变, evaluator 内部实现可自由重构

## Traceability

每个变更项将通过 OTel span 监测:
- `stage=lex` / `stage=parse` / `stage=evaluate` / `stage=serialize` 各 span 正确聚合
- `ReactorTrace.snapshot()` 在测试内部断言 span 树形状
- 失败时 trace 自动携带 IO 路径 + env 快照 + error message
